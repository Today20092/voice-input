# FUTO Voice Input 1.4.6 Share beta 2

This prerelease combines the integrated ticket branches for testing on an ARM64
Android device. The standalone APK uses application ID
`org.futo.voiceinput.moonshine`, version code 63, and the existing release signing
key. It updates the existing standalone installation. Android may prevent a
direct downgrade to an older version code. The stable in-app updater does not
offer prereleases.

## Included changes

- FUTO Keyboard provider setup and updated keyboard help.
- IME text insertion bound to the current input session.
- Language controls that follow the selected model and clearer Model Options.
- Nemotron installation excludes test audio; interrupted model downloads retain
  resumable progress and explain when a file must restart.
- Moonshine reports backend failures and releases native state safely.
- Waveform and provisional transcript remain visible together.
- Explicit microphone selection, including supported Bluetooth routes, with
  interruption handling and recording-session ownership checks.

## What to test

1. Set up FUTO Keyboard, dictate into multiple apps, change fields, cancel, and
   check that text never enters a previous editor.
2. Change models and languages, inspect Model Options, and retry interrupted
   downloads without deleting valid files.
3. Check simultaneous live text and waveform in both the IME and recognition
   activity, including large text and TalkBack.
4. Select a real Bluetooth headset, disconnect it during dictation, and check
   the documented interruption behavior and retained speech.
5. Run long Moonshine dictation and report the device, model, duration and result.

## Validation and remaining work

Publication requires standalone unit tests, standalone lint, Android UI-test
compilation, native Harper tests, APK assembly and package/signature verification
in the release workflow. UI-test compilation does not mean the tests ran on a
device.

Integrated physical-device, headset, TalkBack and long-dictation checks remain
open. The existing retained-data emulator has installation/storage constraints.
This beta collects test results; it does not close those acceptance criteria.

Safe manual model updates, reactive upgrade notices, bounded streaming recovery,
the transcribe.cpp adapter and its optional models are not included. The separate
intermittent-waveform report still needs a reproduction. See `tickets.md` and
[`docs/plans/share-beta-finish.md`](../plans/share-beta-finish.md) for remaining work.

Beta 1's build failed before publication. Its tag remains unchanged; this beta
will use a new tag and tested source commit.
