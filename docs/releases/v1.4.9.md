# FUTO Voice Input 1.4.9

A smaller app with lower avoidable audio allocations and more consistent cleanup,
without removing recognition models or changing the default model.

## Smaller download and native installation

The verified integration APK shrank from 133.33 MiB in 1.4.8 to 100.26 MiB:
about 33 MiB, or 24.8%, smaller. Extracted native libraries use about 137.74 MiB
less disk space. Release debug information is retained separately for diagnosis
instead of being shipped inside the app. All 29 native libraries, CPU variants,
OpenCL support and the exact pinned Whistle executable are retained.

These are build and disk-size measurements, not measured inference RAM or speed
improvements. The versioned release build runs the same packaging checks again.

## Recording, history and model comparison

- Live dictation and audio-history retranscription now share S1-mini, Harper
  Basic text cleanup and personal vocabulary processing. History previously
  skipped Harper. Existing language gates, cleanup preferences, valid-empty
  output and successful-only saved transcript replacement remain intact.
- Model comparison loads one canonical recording at a time while preserving
  isolated decoder inputs, raw transcripts, scoring and timing rules. At eight
  180-second recordings, this avoids retaining about 76.9 MiB of canonical PCM.
- Streaming finalization avoids an unused full-recording copy: about 11 MiB for
  a 180-second recording. Complete audio history and final-only recognition
  inputs remain preserved, and recognition timing keeps its previous meaning.
- Shared recognition-model construction reduces repeated configuration logic
  while preserving variants, language choices, warm production state and
  independent comparison runs.

The allocation figures are calculations for those recording lengths, not
measured phone PSS, latency, battery or thermal results. The earlier Phonon
full-volume audio fix remains included.

## Transcript-capture settings

Capture loading, deletion, clearing and export preparation run off the UI thread.
Retention/loading avoids decoding the same captures twice. Storage failures show
an error and Retry instead of appearing as an empty list or successful deletion.
A failed list refresh after a successful action retries loading without repeating
the completed action.

Transcript capture still requires explicit consent, retains the latest ten runs
for up to seven days, and remains separate from audio history. Standard diagnostics
continue to exclude audio and dictated text. Broader diagnostic privacy, retention
and delivery follow-ups remain separately tracked.

## Install and verification

Install `futo-voice-input-moonshine-v1.4.9.apk` over the existing app. Version code
80 is higher than 1.4.8's 79. The production application ID and signing configuration
are unchanged; models, settings and recordings are preserved. No model removal,
re-download or uninstall is required by these improvements. Orukeet stays default.

The implementation merged in [PR #37](https://github.com/Today20092/voice-input/pull/37).
Its [final integration CI](https://github.com/Today20092/voice-input/actions/runs/40108948096)
passed 260 JVM tests with zero failures/errors/skips, release lint, Android-test
compilation, model package/reference checks, signed ARM64 assembly, APK contents
and signature checks, pinned Whistle verification and matching separate native
symbols. The release-tag CI repeats these checks for this version.

All further testing after the maintainer's RAM constraint runs in CI. No physical
phone was available: instrumentation/Compose tests were compiled, not executed,
and actual microphone/editor behavior, model/CPU/OpenCL smoke tests and device
performance measurements remain pending. Architecture review ran inline because
review agents could not initialize; it was not an independent-agent review.
