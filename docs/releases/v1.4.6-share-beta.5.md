# FUTO Voice Input 1.4.6 Share beta 5

This ARM64 prerelease builds on Share beta 4 and includes commit `cec0868`.
The signed APK updates the existing standalone app, application ID
`org.futo.voiceinput.moonshine`, with version code 66. Install it over the
existing app to retain settings and downloaded models. The stable updater
does not offer prereleases.

## Changes since beta 4

- Carry the beta's fix for [issue #7](https://github.com/Today20092/voice-input/issues/7).
  Nemotron 3.5 requires only its four recognition files; unused test audio no
  longer blocks installation. Android rejected `test_wavs/en.wav` and
  `test_wavs/ja.wav` as temporary-file prefixes in 1.4.5. The shared resumable
  downloader supports nested paths, and a new Android regression exercises
  those old paths and verifies the download completion marker.
- Match the FUTO Keyboard microphone drawable to the settings icon size,
  changing its intrinsic size from 72 dp to 24 dp, from commit `cec0868`.

## Test the Nemotron 3.5 download

1. Install the attached APK over your current standalone installation. Do not
   uninstall the app or clear its storage.
2. Open Model Options and find Nemotron 3.5 Multilingual. Continue or retry its
   incomplete download. Previously validated files should be retained.
3. Confirm that the four required files finish and the model becomes available
   for selection. `test_wavs/en.wav` and `test_wavs/ja.wav` are no longer required
   and should not block completion.
4. Select Nemotron 3.5, choose a recognition language, and dictate a short phrase.
5. Report the result on issue #7 with your phone, Android version and this beta
   version. If it still fails, reproduce it and attach a standard bug report
   from the app's diagnostics. Transcript-inclusive diagnostics are unnecessary.

Also check the microphone icon in FUTO Keyboard and continue the
[beta 3 phone test plan](v1.4.6-share-beta.3.md#what-to-test).

## Verification and limits

The issue #7 Android regression uses fixed HTTP payloads through the real
download activity. It verifies nested-file installation and completion, not
native recognition quality or a complete download from Hugging Face.
All 201 local JVM tests passed, and the Android regression passed against the
beta 4 downloader retained in this release.
The release workflow runs unit tests, lint, Android-test compilation, native
Harper checks, signed APK assembly and package/signature verification.
