# FUTO Voice Input 1.4.6 Share beta 3

This ARM64 test prerelease updates the existing standalone installation with
application ID `org.futo.voiceinput.moonshine`, version code 64 and the existing
release signer. The stable updater does not offer prereleases.

## Changes since beta 2

- Settings predictive-back navigation and overlapping text fixes.
- Explicit pinned model updates stage and validate assets while retaining the
  working installation. Activation waits for recording and runtime ownership.
- Reactive repair and optional upgrade notices use lifecycle readiness. Production
  has no declared successor, so this beta invents no upgrade offer.
- Model loading and finalization treat exhausted memory as terminal, preserve
  retained audio and suppress stale or canceled results without recursive retries.
- Failed loading invalidates the installed version actually attempted, including
  a supported older version, while cancellation and OOM preserve its marker.

## What to test

1. Update the standalone app, select an installed model, and dictate from FUTO
   Keyboard and the recognition activity. Change fields, cancel and repeat.
2. Check settings navigation, large text and spoken TalkBack. Test a real
   Bluetooth headset, including disconnection during dictation.
3. Run short, approximately 30-second and at least two-minute Moonshine dictation
   with pauses and uninterrupted speech. Record phone/Android/model/settings,
   transcript continuity, memory and Stop-to-final time; measure S1 separately.

## Validation limits

Publication is gated by combined local unit/build/lint and disposable-emulator
checks, followed by signed CI packaging, native Harper checks and downloadable
APK package/signature/hash verification. Emulator session checks use injected
backends and pinned payload fixtures; they do not establish native speech quality.

Physical phone/editor/FUTO Keyboard interoperability, headset routing, spoken
TalkBack, real-engine successor reload and notice clearance, long-dictation
continuity/memory/latency, catalog calibration and complete attribution remain
open. The original beta 1 packaging exception remains unproven. The intermittent
waveform report still needs a reproduction.

Automatic streaming recovery remains disabled because no supported recoverable
native failure category was established. The transcribe.cpp adapter remains an
isolated experiment with no production promotion; ASR4ALL Small and Parakeet 110M
remain deferred. This beta does not close tickets or authorize the final master
merge. See [the active queue](../../tickets.md).
