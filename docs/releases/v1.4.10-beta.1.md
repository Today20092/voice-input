# FUTO Voice Input 1.4.10 beta 1

This beta improves diagnostic privacy, transcript-delivery records and failure
reports, and adds an optional way to skip AI rewriting for short transcripts.
Orukeet remains the default recognition model. Existing model selections,
cleanup preferences, saved recordings and signing configuration are preserved.

## Diagnostic privacy and delivery

- Ordinary/native logs and stored S1 reports use bounded technical metadata;
  dictated text, vocabulary, paths and raw exception/loader messages are excluded.
- Transcript captures, interrupted temporary files and cached transcript exports
  have explicit retention/size limits. Deleting captures invalidates their cached
  exports. Audio history retains its separate policy.
- Captures distinguish prepared text from an accepted or rejected Android handoff.
  Canceled/reset generations cannot save a stale delivered capture. Older captures
  show delivery as unverified. Android acceptance does not prove another app
  displayed the text.
- An accepted IME commit remains accepted if switching back to the keyboard fails;
  the switch failure is recorded separately. Diagnostic/resource failures cannot
  replace cleanup results, cancellation or the original recognition error.
- Failed transcript sharing removes the prepared archive and preserves the
  original failure for the existing error/Retry interface.

These implement source fixes from [#19](https://github.com/Today20092/voice-input/issues/19)
and [#21](https://github.com/Today20092/voice-input/issues/21). Transcript capture
still requires explicit consent; standard diagnostics remain content-free.

## More useful failure reports

Reports add bounded local event ordering and collection-mode history, model-load
configuration where known, S1 run joins, and recording/VAD/drain counters. Empty
recognition is distinguished from the available capture evidence without claiming
that the microphone captured silence. Model/history operation failures have
specific technical categories. Archives explain units, unavailable fields,
writer losses and export trimming; unknown sizes are not zero transferred bytes.
Unexposed native configuration and prior-process writer-drop counts remain
unavailable. These changes address [#23](https://github.com/Today20092/voice-input/issues/23).

## Optional short-transcript bypass

**Transcript Cleanup → Rewrite preferences → Skip short transcripts** is off by
default. When enabled, eligible English transcripts of 1–9 words skip S1-mini if
they contain none of the requested fillers, correction phrases or repeated words.
Ten or more words keep the normal rewrite path. Basic text cleanup and personal
vocabulary still run afterward. The option does not enable AI rewrite or download
a model. Short text can still benefit from grammar/style changes, so leave this
option off when those edits matter. See [#39](https://github.com/Today20092/voice-input/issues/39).

## Install and verification

Install `futo-voice-input-moonshine-v1.4.10-beta.1.apk` over the existing app after
the beta build is available. Version code 81 is higher than 1.4.9's 80. The
production application ID and signing certificate configuration are unchanged;
uninstalling or clearing storage is unnecessary. This is a prerelease for later
maintainer testing, not a claim that physical-phone verification has completed.

At preparation, [earlier CI for d9097f5](https://github.com/Today20092/voice-input/actions/runs/40112986427)
passed 267 JVM tests, lint, Android-test compilation, signed ARM64 assembly and
packaging checks. That result predates the final diagnostics and short-bypass
changes. [Integration CI for 2d6c497](https://github.com/Today20092/voice-input/actions/runs/40114736456)
was still running. The versioned beta-tag workflow must verify this exact beta
commit; its success is not claimed by these notes.

The separate [Moonshine runtime candidate](https://github.com/Today20092/voice-input/actions/runs/40113425674)
was also running. This beta retains the existing production Moonshine runtime;
it does not claim to fix the [OnePlus native crash, #41](https://github.com/Today20092/voice-input/issues/41).
S1 speculative decoding remains disabled in normal builds. The first experimental
proof encountered a host compilation error; its source fix is included, while
proof/parity and Android speed/memory evidence remain pending. No speculative
speedup or experimental runtime is enabled by installing this beta.

All builds and automated execution for this work run in CI under the requested
low-memory workflow. No local phone or emulator verification is claimed.

## Maintainer checks after installing

1. Try normal voice-keyboard and speech-popup dictation, then audio-history
   retranscription. Cancel during recording/processing and check that no late
   text is inserted and failed/canceled retranscription preserves the saved text.
2. With harmless test text and explicit transcript-capture consent, inspect raw,
   cleaned/prepared and delivered stages. Check cancellation, standard versus
   transcript-inclusive export, sharing errors/retry, and deletion of captures.
3. Confirm **Skip short transcripts** starts off. If testing it, compare a short
   clean phrase with a phrase containing a filler/correction/repeated word and a
   ten-word phrase; then check Basic cleanup and personal vocabulary still apply.
4. On the affected Poco, retry the old Orukeet recording and retain a reviewed
   standard report if it still fails. [#8](https://github.com/Today20092/voice-input/issues/8)
   remains open. Treat OnePlus Moonshine #41 separately; its proposed runtime fix
   needs its own candidate and affected-phone evidence.

Physical microphone/editor interoperability, accessibility, detailed-mode
overhead and full-catalog performance remain pending under #15/#17. Report the
installed beta/build and actual scenario results rather than treating Android-test
compilation or earlier CI as device evidence.
